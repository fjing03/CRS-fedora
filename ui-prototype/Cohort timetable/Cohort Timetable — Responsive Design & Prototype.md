# Cohort Timetable — Responsive Design & Prototype

## Objective

Redesign the Cohort Timetable page for mobile phones and all iPad/tablet screen sizes.

**Start by building a standalone responsive HTML prototype. Do not modify the actual CRS system.**

Use your own design judgement and creativity. No need to discuss every design decision with me first.

## Step 1 — Identify Current UI Issues

Before designing, carefully inspect all screenshots of the current Cohort Timetable.

Identify existing UI/UX problems, especially:
- Layout and information hierarchy.
- Spacing, sizing and alignment.
- Navigation and component arrangement.
- Readability and touch accessibility.
- Responsive limitations and unnecessary scrolling.

Use these findings to guide the redesign. Do not blindly copy the current layout if it has usability problems.

## Step 2 — Responsive Prototype

Create a responsive prototype that:
- Supports mobile phones, iPad Mini, standard iPads and larger iPad screens.
- Maintains approximately 95% consistency with my existing CRS design.
- Uses touch-friendly controls with at least **48px × 48px** touch targets where applicable.
- Avoids horizontal overflow, clipped content and poor spacing.
- Preserves important information and existing functionality.
- Uses responsive layouts designed for touch interaction, not simply a scaled-down Desktop layout.

## Important — Preserve Desktop Design

**Large-screen, non-touch Desktop view must remain almost unchanged.**

- Maximum design changes: approximately 10%.
- Ideally, keep changes around <= 3% where possible.
- Focus improvements mainly on mobile and tablet layouts.
- Do not unnecessarily redesign, rearrange or restyle existing Desktop components.
- Preserve existing Desktop layout, spacing, colours and interactions unless a genuine issue requires adjustment.

## Development Rules

- Use your own judgement to identify and improve responsive design issues.
- Follow the existing CRS design language and the provided prototype references.
- Build and test the standalone HTML prototype across different screen sizes.
- Do not modify the actual CRS source code or existing prototype references.
- Keep the prototype separate from the actual system.

**Final Goal:** A polished, touch-friendly Cohort Timetable experience on mobile and iPad, while keeping the existing Desktop design virtually unchanged.
