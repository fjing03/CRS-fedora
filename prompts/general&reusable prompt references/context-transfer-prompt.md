I am moving from this current chat session to a **new AI session**.

The current session is an older, less capable AI, while the new session will be a **smarter AI**. Before I switch, I want you to extract and organize the **most important knowledge, decisions, requirements, preferences, project context, and ongoing work** from this entire chat.

The goal is to create a **context transfer document** that I can paste into the new AI session so that it can continue working with me without requiring me to explain everything again.

### 1. Extract the Important Context

Review the entire chat history and identify information that is still useful for future conversations.

Focus on:

- My **projects and assignments**
- Project background and objectives
- Technologies, frameworks, tools, and systems I use
- Current project structure and implementation details
- Requirements and constraints
- Decisions that have already been made
- Problems that have already been identified
- Solutions that have already been discussed or implemented
- Important terminology and naming conventions
- Academic requirements and assignment requirements
- Writing style and formatting preferences
- Learning preferences that affect how answers should be given
- Important instructions I repeatedly gave
- Ongoing tasks that are not yet completed
- Important context that the new AI would otherwise need to ask me again

### 2. Separate Facts from Temporary Conversation

Do **not** simply summarize the conversation chronologically.

Instead, extract the **knowledge that should survive into the new session**.

Prioritize information that is:

1. **Important**
2. **Repeated**
3. **Still relevant**
4. **Required to continue my work**
5. **Likely to prevent the new AI from making mistakes**

Do not include:

- Casual conversation
- Repeated explanations
- Temporary questions that are already resolved
- Unimportant examples
- Redundant information
- Old information that has clearly been replaced
- The AI's own unnecessary commentary

### 3. Preserve Important Contradictions or Unresolved Issues

If the conversation contains conflicting information, do **not silently choose one**.

Clearly label it as:

- **Confirmed**
- **Previously decided**
- **Unconfirmed**
- **Conflicting information**
- **Still needs confirmation**

This is important because I do not want the new AI to assume something is true when it was only a previous suggestion.

### 4. Preserve My Working Preferences

Extract the instructions that affect how I want the AI to work with me.

For example:

- My preferred English level
- Preferred explanation style
- Preferred formatting
- How I want academic writing to sound
- How I want coding feedback to be given
- Whether I prefer simple or technical explanations
- Any restrictions I repeatedly stated
- Any specific rules I gave for assignments or projects

Do not invent preferences that I never stated.

### 5. Preserve Project State

For every major project or assignment, identify:

**Project / Assignment Name**

- Purpose
- Current status
- Technologies/tools
- Main requirements
- Completed work
- Current problems
- Decisions already made
- Pending work
- Important files/pages/components if mentioned
- Important constraints
- Next logical steps

### 6. Preserve Important Technical Context

If we discussed coding or system development, extract the technical knowledge that the new AI needs to continue the work.

Include things such as:

- Architecture
- Frameworks
- Programming languages
- Database
- UI structure
- Important routes/pages
- Components
- APIs
- Existing implementation decisions
- Known bugs
- Responsive behaviour
- Naming conventions
- Technical constraints

**Do not rewrite or redesign my existing system.** Only record what was actually established in the conversation.

### 7. Preserve Academic Context

For assignments, reports, essays, practicals, or exams, extract:

- Assignment requirements
- Rubric-related requirements
- Selected topics/models
- Required format
- Important lecture-note restrictions
- Referencing requirements
- Writing style requirements
- Questions that have already been answered
- Areas that are still incomplete

### 8. Writing Style Profile

Create a separate section describing **how I write**, based on my actual writing samples.

Do not just say "B1 English".

Analyze:

- Vocabulary level
- Sentence structure
- Grammar patterns
- Paragraph structure
- Academic tone
- Common transition words
- Repetition patterns
- Typical sentence length
- How technical terms are introduced
- How I explain problems and solutions

The purpose is for the new AI to reproduce my writing style rather than automatically upgrading my English to native or professional English.

### 9. Important Rules for the New AI

At the end, create a section called:

**"Instructions for the New AI"**

Write the most important instructions that the new AI should follow when working with me.

These should be written as direct instructions, for example:

- Do not assume information that has not been confirmed.
- Check existing project context before suggesting changes.
- Preserve existing implementation decisions unless I ask for changes.
- Follow my specified writing style for academic work.
- Ask when important information is missing instead of guessing.

Only include instructions that are actually supported by my previous conversation.

### 10. Final Output Requirements

Make the final result **compact but information-dense**.

Do not produce a long chronological summary of the chat.

Organize it into clear sections such as:

1. **User Profile & Working Preferences**
2. **Academic Context**
3. **Projects & Assignments**
4. **Technical/System Context**
5. **Important Decisions**
6. **Known Problems & Solutions**
7. **Current/Pending Tasks**
8. **Writing Style Profile**
9. **Important Constraints**
10. **Instructions for the New AI**
11. **Unresolved / Needs Confirmation**

Use bullet points and short explanations where possible.

### Most Important Rule

Think of this as creating a **handover document between two AI systems**.

The new AI should be able to read this document and immediately understand:

**Who I am → what I am working on → what has already been done → what decisions were made → what problems exist → how I want the AI to respond → what still needs to be done.**

Do not preserve everything.

Preserve the **knowledge that matters**.
