# Proposal: arrange-intent-session-choice

**Origin:** live user dead-end report 2026-10-15 — staff 5770 booked a B009 (lab, P sessions only) slot from the venue page; their only conflict subject is `L`-type; the consumer's fallback fired *"is conflicted"* — truthful in effect, imprecise in cause (FR 4.7 venue-type ineligibility). Explored & grilled same day: `.sdd/changes/arrange-intent-session-choice/explore-brief.md` (FROZEN baseline for this proposal; user decisions baked in).
**Layer:** Producer modal + handoff contract (Livewire view + component payload, shared service) + consumer fallback prefill & honest copy. **No DB/schema change, no write-path/OCC/engine change.**
**Sequencing:** lands BEFORE `full-block-reservation` (Fix 3) per user-approved recommendation; resolves U2a's deferred "is conflicted" copy item, keeping Fix 3 single-purpose.

## Why

The U2a handoff (`bookVenue` → `/replacement-arrangement?venue&date&time&from=venue-timetable`) carries no class context — deliberately, because the venue page then had none. Consequence: the consumer cannot auto-select deterministically; a venue-ineligible subject pick dead-ends with vague copy. Meanwhile the codebase already holds every fact needed to fail early or never dead-end: per-session types (`coursesPayload`), the consumer's venue-type matrix (`venueEligible`), and a **native pinned-session contract** (`?session=<id>&week=<n>` → server-resolved, ownership-checked, facts-hydrated — `ReplacementArrangement::pinnedSessionPayload`).

This change moves the class choice to the click of intent (a modal on the venue page at the moment of Arrange), restores the frozen template's full handoff contract (`code`+`cohort` — the template's `bookVenue` always carried them; U2a omitted them only for lack of producer context), and adds a modest consumer fallback so intent arrivals that bypassed the modal still prefill.

## In scope

1. **Producer modal — "Select a Session"** (user-frozen design):
   - Trigger: the venue page's existing **Arrange** button (tooltip affordance exists only on bookable cells; too-soon/no-fit cells cannot reach the modal).
   - Title **"Select a Session"**; **subject dropdown + session dropdown** listing **only compatible items**: subjects = only modules owning ≥1 session whose type is allowed in the venue's room type (P→Lab incl. B006 CiscoLab, T→Tutorial, L→LectureHall — same mapping as the consumer's `venueEligible` matrix); B005 additionally excludes sessions whose cohorts include a `D*` programme (doc's enforced no-Diploma rule; B006 stays priority-not-ban).
   - Auto-preselection: first compatible module in subject-dropdown display order; within it, first compatible occurrence in payload session order (user-confirmed Q2; no closeness heuristics).
   - Buttons **[Cancel] [Arrange]**; **[Cancel]/Escape closes without navigating** (nothing persisted). **[Arrange] requires a compatible session** → dead-end impossible by construction.
   - Zero-compatible case: no dropdowns; honest message *"None of your classes can run in {venue} — {room type} hosts {type} sessions only."* + **[Cancel]**. If the type filter passes but the **duration-fit** fails for every remaining session (round-1 🔴3), the message extends: *"…and none of them fit before the day end ({end time})."*
   - **Duration-fit rule (round-1 🔴3):** a compatible session is offered only if its span (`duration × 2` slots) starting at the intent slot's hour ends at or before the venue grid's last slot (`hours.length`, shared constant) — sessions that would overrun the day end are not offered (same compatible-only policy). This makes the producer guard session-accurate beyond the default `BOOK_SPAN = 4` (spans are half-hour slots: the default `BOOK_SPAN = 4` (=2h) path never dead-ended; only spans >4 slots on short day-end windows previously did — a span ≤ `hours.length − startHour` is offered, otherwise excluded).
   - Shared-infrastructure mandate (user): modal markup as a new Blade partial (`resources/views/partials/`), theme.css tokens + existing modal classes/idiom (`ui-class-detail-modal` pattern); mobile ≤768px uses the shared bottom-sheet pattern (§10.0 rule 9).
2. **Producer payload:** the venue page currently emits only *this venue's* events; the modal needs the lecturer's own classes across all venues. `VenueTimetable` gains that payload — built by a **shared service extracted from `ReplacementArrangement::coursesPayload()`** (OOP promotion §10.4: the extraction creates the second consumer of this shape under an explicit user mandate — "modal design use oop/shared file" — valid override of promote-on-3rd-duplication, recorded under "Promoted to shared", NOT as a satisfied 3-duplication claim). Per-session facts carried: module code/name, session id, type, venue, duration, day-of-week, start/end times (the label builder renders "{day abbr}, {DD Mon YYYY} · {HH:MM}–{HH:MM}" for the occurrence's instance in the booked week — the shared service must emit these, they are NOT in today's `coursesPayload`), cohorts (+labels for the dropdown text and the B005 rule). Additionally, the shared service emits `sessions` as an ARRAY ordered canonically by `(day_of_week, start_time, id)` — the preselection rule's "payload session order" means THIS array order (today's object-keyed map iterates by numeric id, which is not the intended order).
3. **Handoff URL contract (user-confirmed; 8-param — the brief's 7-param draft gains the required `week`, see round-1 fix):**
   `/replacement-arrangement?venue={code}&date={DD Mon YYYY}&time={HH:MM}&from=venue-timetable&code={module}&session={class_session_id}&cohort={label}&week={replaced-occurrence week, 1-based}`
   - `code`/`cohort` — the frozen template's originals, now genuinely filled (consumer parses both today; `cohort` is parsed-but-unused — restored as contract, not function).
   - `session` + `week` — feed the **existing** pinned-occurrence contract server-side (`pinnedSessionPayload` returns null without `week`: it is REQUIRED; ownership-checked resolve + facts hydration; `week` 1-based per its existing convention). Producer converts its 0-based `currentWeek` → `week = currentWeek + 1` at handoff.
   - **`week` semantics (⛔ pinned by this proposal):** the pin names the pair `(replaced occurrence's session id, replaced occurrence's week)` = the venue cell the user clicked — the natural “replace this occurrence” default. If the user later picks a different original slot in the slot picker, the consumer's existing picker overwrite rule wins (arrangement `:2922–2924`) — no new overwrite behavior added.
4. **Consumer fallback prefill (the "B" decision)** — for intent arrivals that bypassed the modal (hand-typed/book-marked full-intent URLs without `session`):
   - Fires only when `pendingBookingIntent` exists, no subject picked yet, **and** no `session` param arrived (session presence = modal context, short-circuits the fallback — one automation never fights the other).
   - Matches the modal's rule: session-occurrence grain vs the intent venue's allowed types (+B005 cohort rule, + the SAME duration-fit check against the intent slot — 🔴3 symmetric so the fallback can never preselect a session the modal would have excluded); first compatible module in dropdown order, first compatible occurrence in payload order.
   - **Occurrence binding is a real consumer bridge (round-1 🔴2):** the fallback sets `window.pinnedOccurrence = { sessionId: O, week: intentWeek + 1 }` client-side — where `intentWeek` is the intent's 0-based week index (date-resolved by `resolveBookingIntent`, same conversion as the producer's `currentWeek`: both are 0-based, both hand off 1-based; mirroring the slot-picker's own pin rewrite at arrangement `:2922–2924`) BEFORE triggering the subject bind, so `applySubjectChange`'s wanted-session logic (`:2697–2701`) binds the *compatible* occurrence — not the module's first session, which for a mixed-type module (AMCS2093 = L+P+T) can be type-incompatible and recreates the dead-end. Blade-JS change (no PHP); the earlier “Blade only / zero PHP” impact claim stands, with this bridge called out.
   - **Manual picks are never overridden** — a user-picked incompatible subject is never silently switched; the banner instead names it.
   - **Bare `?venue=` deep-links do NOT prefill** (no booked slot exists; grid stays locked as frozen).
5. **Consumer honest-copy set** (retires “is conflicted — please select an available slot manually.” entirely from `renderBookingIntent`; wording set user-frozen in grilling, extended by the round-1 duration branch):
   - Venue-type ineligibility (picked subject): *"{module}({type}) has no {required-type} sessions that can run in {venue} ({room type})."*
   - **Day-end/duration (round-1 🔴3 branch):** *"Your class runs longer than the time left before the day end ({end time}) — pick an earlier slot or change the subject to a shorter session."* (fires only when span-fit fails while the cells are otherwise free — distinguishes from the occupancy branch).
   - Occupancy (post-arrival grid change): *"Your booked slot ({day}, {date} · {time}) is no longer available on the {venue} grid (a block already holds it) — pick another available slot manually."*
   - Too-soon: unchanged frozen wording (*"is within 3 working days — please pick a later slot manually."*).
   - **Attribution-note host (round-1 🟡, pinned here):** the auto-pick note rides the EXISTING pre-selection toast (same host, extended text): *"Pre-selected {module}({type}) — auto-picked because its sessions fit {venue}; change if needed."* No new toast host.
   - **Occurrence label format (round-1 🔴4 — user decision 2026-10-15):** session-dropdown entries read *"{module} {name} ({type}) · W{n}, {day abbr}, {DD Mon YYYY} · {HH:MM}–{HH:MM}"* — exactly: "AMCS2093 Advanced Web Programming (P) · W5, Thu, 22 Oct 2026 · 14:00–16:00" — module, subject name, type, the occurrence's week + date in the booked week, and start–end time (week label uses the same 1-based W-number the UI shows, e.g. W5 = week index 4) (user asked for name + date + end time over the width-conscious default)
6. **Tests + docs:** venue-page modal spec (filtering incl. B005 rule + duration-fit, preselection, zero-compatible, Cancel, handoff URL equality); consumer fallback spec (bypass prefill incl. occurrence binding, manual-pick-no-override, four copy branches, session-param short-circuit); **round-1 🔴1 — U2a contract change surfaced:** `tests/venue-book.spec.ts` is MODIFIED by this change by design — with the modal interposed between tooltip and consumer, **U2a-T3 (click #tooltipBookBtn → navigation) must pass through the modal** (open modal → Arrange; T2's tooltip-sentence assertions survive); not a regression — the designed contract change, recorded in the changelog as such.

## Success criteria

1. From the venue page: Arrange on a bookable cell → modal opens with only compatible subjects/sessions preselected per the ordering rule; Cancel/Escape returns to the venue page with nothing persisted; zero-compatible renders the honest message with [Cancel] only.
2. Confirming [Arrange] navigates with the full 8-param URL; the consumer pins the exact occurrence (server-resolved, ownership-checked), lands on that week, and auto-selects the booked slot as a pre-selection with the existing toast/pulse — no new consumer selection machinery (the fallback's `pinnedOccurrence` bridge reuses the pin path).
3. Full-intent arrival without `session` (modal bypassed): the consumer falls back to the same matching rule (type + B005 + duration-fit), preselects the compatible occurrence via the pin bridge, and the attribution note names the auto-pick; a user's manual pick is never overridden (naming copy appears instead).
4. The word "is conflicted" no longer appears in the consumer banner; each remaining branch carries its precise cause (ineligibility / duration-day-end / occupancy / too-soon).
5. Session-occurrence compatibility modal/fallback filters agree one-source-of-truth (P→Lab ∪ CiscoLab, T→Tutorial, L→LectureHall + capacity NOT re-applied at the modal + B005 no-Diploma + duration-fit) — with the vocabulary normalization obligation (vendor `cisco_lab` maps differently in the two payloads; design fixes the canonical key).
6. Gates: pint ✓, phpstan 0, phpunit green; Playwright — venue-db / venue-timetable / type-labels stay green, **venue-book evolves with the modal (designed contract change) and stays green post-update**, new specs green; the full-suite scope question remains governed by U2a's T12 decision (not re-opened here).
7. Changelogs record the change + every user-decision copy string with decision date 2026-10-15.

## Risks / mitigations

- **Intent × pinned-session interplay** (week jump from `pinnedSession` vs the intent's own week jump): the pinned contract sets `weekNav` before grid build; `consumeBookingIntent` re-checks the day/hour on the bound grid — verify the double-jump collapses (design obligation: one deterministic landing path; explicit test).
- **Matrix drift** (venue room-type ↔ session-type mapping duplicated producer vs consumer, `cisco_lab` mapped differently in the two payloads): design obligation — server-side canonicalization in the shared payload service (canonical key + `P` admissible in `Lab` ∪ `CiscoLab`), so the modal filter is exact; the "no `ui-common.js` change expected" claim is revisited in design only if client-side sharing demands it.
- **Payload size:** lecturer-scoped sessions only (≈ a few dozen rows); negligible.
- **Ownership/fabrication safety** on `?session=` already enforced server-side (`pinnedSessionPayload` ownership check) — the modal merely sends real ids; tampered ids resolve to null exactly as today.
- **False positives in compatible-only lists** (e.g. capacity edge): the modal filter intentionally ignores capacity (it lives in the engine + the consumer dropdown filter); a session may be eligible-by-type yet capacity-rejected at submit — the honest engine alert covers it; noted so no one "fixes" the modal later by duplicating capacity logic.
